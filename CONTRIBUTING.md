# Как предложить изменение

[English](CONTRIBUTING.en.md) · [Вики](https://x4wiki.com/) · [Формы Issues](https://github.com/dmitriishobolov/x4wiki-Contribute/issues/new/choose)

## Предложение без Git и программирования

1. Войдите в GitHub и откройте **Issues → New issue**.
2. Для новой темы выберите **Новая статья / дополнение (RU)**. Для ошибки
   в существующей статье - **Исправление статьи / примера (RU)**.
3. Заполните обязательные поля. Добавьте ссылку на страницу вики; если статьи
   ещё нет, опишите нужную тему. Приложите короткий собственный пример кода,
   если он помогает объяснить предложение.
4. Укажите версию X4 и модов, источники и границы проверки: только идея,
   чтение исходника, отдельный тест или выполненный игровой сценарий.
5. Нажмите **Create**. Сохраните ссылку на Issue: обсуждение и уточнения будут там.

Можно писать по-русски или по-английски. Перевод не обязателен, чтобы предложить
материал; редактор проверит обе языковые версии перед публикацией.

## Пример хорошего исправления

**Страница:** `https://x4wiki.com/pages/register-event`.

**Проблема:** в примере не объяснено, чем имя события отличается от аргументов
callback. Новичок может принять пример за универсальную сигнатуру.

**Предложение:** добавить пояснение, что аргументы нужно сверять с конкретным
отправителем, и привести его короткий фрагмент со ссылкой на источник.

**Проверка:** пока только чтение исходника; в игре пример не запускался.

Это пример оформления предложения, а не подтверждение наличия указанной ошибки.

## Готовая статья через Pull Request

1. Нажмите **Fork** вверху репозитория.
2. В своей копии выберите **Add file → Create new file**.
3. Назовите файл `proposals/ship-hull-example.ru.md`. Используйте латинское
   устойчивое имя, которое отражает тему.
4. Скопируйте [шаблон](templates/article.ru.md), заполните задачу, предпосылки,
   шаги, пример, проверку результата и источники. Для английского текста
   используйте суффикс `.en.md` и [английский шаблон](templates/article.en.md).
5. Нажмите **Commit changes**, затем **Contribute → Open pull request**.
6. Заполните автоматически предложенный шаблон PR. Если было обсуждение,
   добавьте ссылку вида `Related to #12`.

Для исправления существующего материала можно скачать его Markdown внизу
статьи вики и приложить исправленный вариант в `proposals/`. Укажите URL
оригинала и кратко перечислите изменения. Доступ к другим проектам не нужен.

Если удобнее работать через Git:

```sh
git clone https://github.com/YOUR_NAME/x4wiki-Contribute.git
cd x4wiki-Contribute
git switch -c article/ship-hull-example
# Добавьте заполненный Markdown в proposals/.
git add proposals/ship-hull-example.ru.md
git commit -m "Propose ship hull example"
git push -u origin article/ship-hull-example
```

После push откройте PR из своей ветки в `dmitriishobolov/x4wiki-Contribute:main`.
`YOUR_NAME` замените своим именем GitHub; клонируйте собственный Fork.

## Что указать в техническом материале

- Где работает код: XML-патч, MD, AI, Lua UI, FFI или собственная библиотека.
- Версию игры, расширения и место вставки примера.
- Параметры и типы, известные из источника; неизвестное пометьте явно.
- Как независимо проверить результат и какие ограничения остались.
- Ссылки на первичную документацию или собственные авторские материалы.

Не называйте пример проверенным в игре, если был только просмотр кода.
Не присылайте сам мод, его файлы, внутренние документы или полные исходники.
Не добавляйте токены, личные журналы, сейвы и извлечённые оригинальные файлы X4.
Для примера напишите небольшой самостоятельный фрагмент и укажите публичные первичные источники.

## Что происходит после отправки

Редактор проверяет источники, воспроизводимость и область материала, обсуждает
уточнения, затем переносит принятый текст в рабочую копию вики. Там проверяются
перевод, ссылки, примеры и сборка, после чего выполняется публикация. В Issue
или PR можно указать опубликованный URL, когда изменение действительно вышло.
Предложения не публикуются автоматически.
